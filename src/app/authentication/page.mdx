# Authentication

AgentFlow supports API key and JWT-based authentication to secure your endpoints. This page covers setup, middleware configuration, and best practices.

## Authentication Methods

| Method | Use Case | Complexity |
|--------|----------|------------|
| API Key | Server-to-server calls, CLI tools | Simple |
| JWT Token | Frontend clients, user-scoped access | Moderate |

## API Key Authentication

API keys are the simplest way to authenticate. Generate a key and pass it in the `Authorization` header.

### Generate a Key

```bash
agentflow auth create-key --name "my-service" --scopes "workflows:run,tasks:read"
```

Output:

```text
API Key: af_sk_live_abc123def456...
Scopes: workflows:run, tasks:read
Created: 2026-02-21T10:00:00Z
```

### Use the Key

Include the key in your API requests:

```bash
curl -H "Authorization: Bearer af_sk_live_abc123def456" \
  http://localhost:8000/api/workflows
```

Or in Python:

```python
import httpx

client = httpx.AsyncClient(
    base_url="http://localhost:8000/api",
    headers={"Authorization": "Bearer af_sk_live_abc123def456"},
)

response = await client.get("/workflows")
```

## JWT Authentication

For frontend clients, use JWT tokens to authenticate users with scoped permissions.

### Configure the JWT Provider

Set up the JWT middleware in `agentflow.config.yaml`:

```yaml
auth:
  jwt:
    issuer: https://auth.example.com
    audience: agentflow-api
    algorithms:
      - RS256
    jwks_uri: https://auth.example.com/.well-known/jwks.json
```

### Middleware Setup

The authentication middleware validates tokens and attaches user context to each request:

```python
from agentflow.auth import JWTMiddleware, require_scope

# Applied globally in the API server
app.add_middleware(
    JWTMiddleware,
    issuer="https://auth.example.com",
    audience="agentflow-api",
)

# Require specific scopes on individual routes
@app.get("/api/admin/users")
@require_scope("admin:read")
async def list_users(request: Request):
    user = request.state.user
    return await get_users(org_id=user.org_id)
```

### Token Structure

AgentFlow expects JWTs with the following claims:

```json
{
  "sub": "user_123",
  "org_id": "org_456",
  "scopes": ["workflows:run", "tasks:read", "agents:read"],
  "iat": 1740100000,
  "exp": 1740103600
}
```

## Scopes Reference

| Scope | Description |
|-------|-------------|
| `workflows:run` | Execute workflow runs |
| `workflows:read` | List and inspect workflows |
| `workflows:write` | Create and modify workflows |
| `tasks:read` | Read task status and results |
| `agents:read` | List and inspect agents |
| `agents:write` | Create and modify agents |
| `webhooks:manage` | Create and delete webhooks |
| `admin:read` | Read admin-level resources |

## Best Practices

- **Rotate keys regularly** — Use `agentflow auth rotate-key` to rotate API keys without downtime
- **Use least-privilege scopes** — Grant only the scopes each client needs
- **Store secrets securely** — Use environment variables or a secrets manager, never hard-code keys
- **Enable HTTPS** — Always use TLS in production to protect tokens in transit
